1  Overview

This pipeline segments individual bacterial cells in Zeiss Airyscan confocal images of mouse colon tissue sections, then measures per-cell fluorescence intensity in four channels (BFP, GFP, RFP, SYTOX) to quantify osmotic and oxidative stress reporter activity.

Image format

PropertyValue
File formatTIFF, (4, 6323, 6344) uint16 stacks exported from Zen
Pixel size0.035 µm/px (square, confirmed from Zen)
Channel 0 (C1)BFP — constitutive reporter → segmentation input
Channel 1 (C2)GFP — osmotic-stress promoter
Channel 2 (C3)RFP — oxidative-stress promoter
Channel 3 (C4)SYTOX far-red — host nuclear stain (exclusion only)

Critical invariant
Segmentation uses the normalised BFP image. Intensity measurement always uses the raw uint16 stack. These two paths must never be swapped — measuring from normalised images would destroy all quantitative information.

2  Environment setup

There are two separate conda environments. Keep them separate — they conflict.

cellpose (main environment)

Used for everything except the Omnipose baseline: fine-tuning, inference, measurement.

# Create from scratch
conda env create -f environment.yml
conda activate cellpose
pip install -e .

# Or just activate if already set up
conda activate cellpose

Verify GPU is available:

python -c "import torch; print(torch.backends.mps.is_available())"  # macOS
python -c "import torch; print(torch.cuda.is_available())"           # Windows/Linux

omnipose (baseline comparison only)

CPU-only. Used only to run the Omnipose baseline in scripts/run_omnipose_baseline.py.

conda activate omnipose

Getting the fine-tuned model

Fine-tuned weights are too large for GitHub, so models/ is gitignored in this repo. They're hosted separately on the Hugging Face Hub: huggingface.co/aliceh0ng/cellpose-biosensor.

After cloning, pull the model before running the pipeline:

conda activate cellpose
# recommended run: 4stacks_5x5_norm
python scripts/download_model.py

# or a specific run
python scripts/download_model.py --run 5stacks
What this does
Downloads models/finetuned/<run>/ from the Hub and updates models/finetuned/latest_model_path.txt, which the pipeline reads automatically. Skip this step to run with the base cpsam model instead.

Adding your images

data/raw/16bit_all/ doesn't exist yet after a fresh clone (raw images aren't checked into git) — create it and copy your stacks in:

mkdir -p data/raw/16bit_all
cp /path/to/your/*.tif data/raw/16bit_all/

Required file format:

PropertyRequirement
File type TIFF, 16-bit unsigned integer (uint16) — use the 16-bit export from Zen, not the RGB preview/quick-look export
Shape (4, H, W) — one z-plane, 4 channels first. (Z, 4, H, W) is also accepted (max-projected automatically)
Channel order [0] BFP (constitutive → segmentation input) · [1] GFP (osmotic-stress reporter) · [2] RFP (oxidative-stress reporter) · [3] SYTOX (host nuclear stain, exclusion only)
Pixel size 0.035 µm/px — if yours differs, update DIAMETER_PX (round(1.5 / pixel_size))
Format is validated, not assumed
load_stack() in src/io.py checks dtype and shape on load and raises a clear error if you accidentally pass the RGB export instead of the 16-bit one.

Treat data/raw/ as read-only once populated — nothing in the pipeline writes there.

3  Running the segmentation pipeline

There are two ways to run the pipeline: the interactive Jupyter notebook (good for a single image, QC, and exploration) and the batch Python script (good for processing all images at once, or on a cluster).

3a  Notebook — notebooks/06_segmentation_pipeline.ipynb

  1. Activate the environment and open the notebook 
    conda activate cellpose
jupyter lab  # or: jupyter notebook
    Open notebooks/06_segmentation_pipeline.ipynb.
  2. Set the image path and model

    In the configuration cell, edit STACK_PATH to point to your image:

    STACK_PATH = PROJECT_ROOT / 'data/raw/16bit_all/YOUR_IMAGE.tif'

# Model is loaded automatically from latest_model_path.txt
# Set MODEL_PATH = None to use the base cpsam without fine-tuning
MODEL_PATH = None  # or leave as-is to use the recorded fine-tuned model
    You can also adjust the size filter thresholds: 
    MIN_AREA = 100   # px² — remove objects smaller than this (noise)
MAX_AREA = 2000  # px² — remove objects larger than this (debris / host cells)
  3. Run all cells (Kernel → Restart and Run All)

    The notebook will:

    • Load the image stack and model
    • Normalise the BFP channel (p1–p99 percentile stretch)
    • Run Cellpose-SAM on the full image at diameter=43 px
    • Apply size filter (100–2000 px²)
    • Save raw and filtered masks as TIFFs
    • Measure per-cell intensities from the raw uint16 stack
    • Save results as CSV
    • Show QC figures (mask overview, intensity histograms)
Tip — check the mask overview
The notebook shows a 1:8 thumbnail of the BFP channel with red cell outlines overlaid. Zoom into regions with dense bacteria to verify boundary quality before moving to analysis.

3b  Script — scripts/pipeline.py

The script is functionally identical to the notebook but runs non-interactively. It skips images whose CSV already exists — delete the CSV to reprocess.

conda activate cellpose

# Test on a single image first
python scripts/pipeline.py --single 20260416-C3M2_Tcol_1.tif

# Run all .tif files in data/raw/16bit_all/
python scripts/pipeline.py

On a SLURM cluster (Sockeye):

sbatch jobs/pipeline.sh --split all

3c  Key parameters

ParameterDefaultWhat it controls
DIAMETER_PX 43 Expected cell diameter in pixels. Set as round(1.5 / 0.035) (1.5 µm bacteria at 0.035 µm/px). Change if your pixel size differs.
MIN_AREA 100 Minimum cell area in px². Objects below this are considered noise and removed.
MAX_AREA 2000 Maximum cell area in px². Objects above this are considered debris or host cell fragments and removed.
LOCAL_BG False If True, subtracts a per-cell annular ring background (5 px wide) before computing ratios. Recommended for heterogeneous backgrounds.
FLOW_THRESH 0.4 Cellpose flow error threshold. Lower = stricter (fewer, cleaner cells). Raise if cells are being missed in dense regions.
CELLPROB_THRESH 0.0 Cell probability threshold. Raise to require higher confidence before calling an object a cell.
MODEL_PATH auto Path to fine-tuned model weights. Auto-loaded from models/finetuned/latest_model_path.txt. Set to None to use base cpsam.

3d  Outputs

Files written per image
  • data/processed/<name>_masks_raw.tif — integer label mask before size filter
  • data/processed/<name>_masks.tif — final label mask after all filters
  • data/results/<name>.csv — per-cell intensity measurements
  • figures/qc/<name>_masks_overview.png — BFP thumbnail + red cell outlines
  • figures/qc/<name>_intensity_qc.svg — BFP, GFP/BFP, RFP/BFP histograms

The script additionally writes data/results/filter_steps.csv (one row per image: raw cell count and count after size filter).

4  Training your own model

4a  What fine-tuning does

Fine-tuning adapts the Cellpose-SAM (cpsam) foundation model to your specific images using a small number of hand-annotated examples. In practice, 5–9 annotated patches (~500×500 px tiles) is sufficient to meaningfully improve over the base model.

The fine-tuned model is saved to models/finetuned/ and automatically picked up by the pipeline (via latest_model_path.txt).

When to fine-tune
Run the base cpsam on your images first (notebook 02 or pipeline with MODEL_PATH=None). If the segmentation looks reasonable, fine-tuning will likely improve boundary accuracy and reduce false positives. Fine-tuning is especially helpful for unusual cell shapes or dense packing that differs from cpsam's training data.

Step 1 — Export and annotate patches

  1. Export patches from the training image(s)

    Run notebooks/01_tiling_preprocessing.ipynb on your training image. This splits the image into a 3×3 grid and saves BFP patches to data/annotations/images/.

    conda activate cellpose
jupyter nbconvert --to notebook --execute notebooks/01_tiling_preprocessing.ipynb

    Outputs: patch_r0_c0.tif through patch_r2_c2.tif (9 patches)

  2. Open Cellpose GUI 
    conda activate cellpose
python -m cellpose
  3. Annotate each patch
    • Open a patch from data/annotations/images/
    • Set Calibrate diameter to ~43 px
    • Run cpsam as a starting point
    • Correct the masks:
      • Add missed cells (right-click drag to draw outline)
      • Delete false positives (select + Delete key)
      • Fix boundaries where needed
    • Click Save — this writes patch_r?_c?_seg.npy next to the image
    • Repeat for all 9 patches (minimum 5 before first training run)
    Annotation quality matters more than quantity
    A few carefully corrected patches outperform many hastily annotated ones. Focus effort on regions where the base model performs worst.

Step 2 — Fine-tune: notebook 04_finetuning.ipynb

The notebook is the recommended path for local training on a single image.

  1. Open and configure

    Open notebooks/04_finetuning.ipynb. The default configuration works for most cases:

    ANNOT_IMG_DIR = PROJECT_ROOT / 'data/annotations/images'
N_EPOCHS      = 100
LEARNING_RATE = 1e-5
WEIGHT_DECAY  = 0.1
BATCH_SIZE    = 1
VAL_FRAC      = 0.2    # 20% of patches held out for validation
MODEL_NAME    = 'cpsam_finetuned'
  2. Annotation QC cell

    The notebook shows all annotated patches with red outlines. Inspect these before training — if a patch looks wrong, re-annotate it in the GUI before continuing.

  3. Run all cells

    Training runs locally using MPS (macOS) or CUDA (Windows/Linux). 100 epochs takes ~5–15 minutes depending on hardware. Progress is shown per epoch.

    When done, the notebook:

    • Saves weights to models/finetuned/models/cpsam_finetuned
    • Records the path in models/finetuned/latest_model_path.txt
    • Plots training/validation loss curves
    • Compares base cpsam vs fine-tuned on held-out patches (AP@IoU 0.5)
Interpreting training curves
Training loss should decrease steadily. Validation loss should follow (possibly with some noise due to the small val set). If val loss starts rising while train loss keeps falling, you are overfitting — reduce N_EPOCHS or annotate more patches.

Step 2b — Fine-tune: script scripts/finetune.py

Use this when training on multiple annotated stacks (e.g. on Sockeye or after annotating patches from several images).

Prerequisites: data/splits.json (from make_splits.py) and data/annotations.json listing which stacks are annotated.

Example data/annotations.json:

{
  "annotated_train": [
    "20260416-C3M2_Tcol_1.tif",
    "20260416-C3M3_Pcol_2.tif",
    "20260416-C4M3_Dcol_1.tif"
  ]
}
# Give the run a descriptive name
python scripts/finetune.py --run-name 5stacks

# With custom patches directory
python scripts/finetune.py --run-name 5stacks_v2 --patches-dir data/patches/v2

# On Sockeye (SLURM)
sbatch jobs/finetune.sh 5stacks
Run outputs
  • models/finetuned/<run-name>/models/cpsam_<run-name> — weights
  • models/finetuned/<run-name>/run_info.json — date, stacks, AP scores
  • models/finetuned/<run-name>/figures/training_curves.png
  • models/finetuned/<run-name>/figures/val_comparison.png
  • models/finetuned/<run-name>/figures/ap_bars.png
  • models/finetuned/latest_model_path.txt — updated to this run

Step 3 — Evaluate

Check run_info.json for the key metric:

{
  "ap_base":      0.512,   // base cpsam AP @ IoU 0.5
  "ap_finetuned": 0.681,   // fine-tuned AP @ IoU 0.5
  ...
}

AP @ IoU 0.5 > base cpsam → proceed to the full pipeline.

AP ≤ base cpsam — things to try:

  • Annotate more patches, especially in regions where the base model performs worst
  • Increase N_EPOCHS to 200 if val loss was still decreasing at epoch 100
  • Check annotation quality — accidental mis-labels hurt more than fewer clean labels

Hyperparameters

ParameterDefaultNotes
LEARNING_RATE 1e-5 Conservative — avoids overwriting SAM backbone features. From the official Cellpose-SAM colab. Do not increase above 1e-4.
WEIGHT_DECAY 0.1 L2 regularisation. Use as-is.
BATCH_SIZE 1 SAM is memory-heavy. 1 is standard for fine-tuning.
N_EPOCHS 100 Increase to 200 if val loss is still falling at epoch 100.
VAL_FRAC 0.2 Fraction of patches (notebook) or stacks (script) held out for validation.
Cellpose 4.x API note
Use train.train_seg(model.net, ...), NOT model.train(...). The latter is a Cellpose 2.x wrapper and is not the recommended path for cpsam fine-tuning. train_seg returns a 3-tuple: (model_path, train_losses, val_losses).

5  Understanding the CSV output

Each image produces a CSV at data/results/<name>.csv with one row per segmented cell.

ColumnTypeDescription
image_idstrStack filename stem (e.g. 20260416-C3M2_Tcol_1)
cell_idintInteger label from the mask (1-indexed)
area_pxintCell area in pixels
centroid_y, centroid_xfloatCell centroid coordinates (pixels)
bfp_raw, gfp_raw, rfp_raw, sytox_rawfloat Mean pixel intensity per channel from raw uint16 data (ADU)
bfp_bg, gfp_bg, rfp_bgfloat Local background estimate (mean of 5 px annular ring). Zero if LOCAL_BG=False.
bfp, gfp, rfpfloat Background-subtracted intensity (raw - bg, floored at 0)
gfp_over_bfpfloat GFP/BFP ratio. Osmotic stress reporter. NaN if BFP = 0.
rfp_over_bfpfloat RFP/BFP ratio. Oxidative stress reporter. NaN if BFP = 0.
Autofluorescence warning
GFP and RFP channels show substantial signal even when reporters should be OFF — this is fecal autofluorescence, not biological signal. Always background-subtract before computing or interpreting ratios. The BFP distribution should be unimodal (good QC indicator); a long high tail may indicate residual autofluorescence.

6  Tips and common issues

Pipeline

  • Segmentation is slow on CPU — ensure MPS (macOS) or CUDA (Windows/Linux) is active. Check with torch.backends.mps.is_available() or torch.cuda.is_available().
  • "Skip — CSV exists" — the script skips images with existing CSVs. Delete data/results/<name>.csv to reprocess.
  • Too many cells / too few cells — adjust CELLPROB_THRESH (up = stricter, fewer cells) or FLOW_THRESH.
  • Size filter removing real cells — check the area distribution in the CSV (df['area_px'].describe()) and widen MIN_AREA/MAX_AREA accordingly.

Fine-tuning

  • AP does not improve — the most common cause is annotation errors (missed cells, wrongly split/merged cells). Re-examine the validation patches in the GUI.
  • Training loss does not decrease — check that patches are float32 images with at least some cell signal. Fully black patches will not train correctly.
  • MPS autocast warnings during training — these are cosmetic and safe to ignore. They occur because MPS does not support all dtypes used by the autocast context.
  • Saving intermediate checkpoints — Cellpose saves a single final model. If you want checkpoints at intervals, increase N_EPOCHS in stages and run separate training runs.

File paths

Every notebook and script defines PROJECT_ROOT as an absolute path. All data, model, and figure paths are built from it. Never use relative paths like 'data/...' — they silently create folders inside notebooks/ when a notebook is run from that directory.

Display vs. measurement normalisation

UseNormalisationFunction
Cellpose-SAM input p1–p99 percentile stretch → float32 [0, 1] normalize_for_segmentation()
QC thumbnail display p1–p99.9 (avoids autofluorescence blobs compressing range) normalize_for_segmentation(high_pct=99.9)
Intensity measurement None — raw uint16 only extract_intensities(masks, raw_stack, ...)
